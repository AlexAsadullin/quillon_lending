# n8n: приём заявок

Один воркфлоу `shesterenka-leads.json` принимает заявки из двух мест и пишет их в одну Google Таблицу
(лист «Заявки», 9 столбцов — `shesterenka-leads-template.xlsx`):

- **сайт** — вебхук «Заявка с сайта» (`js/config.js` → `FORM_ENDPOINT`);
- **клиентский Telegram-бот** — триггер «Сообщение клиентскому боту». Бот спрашивает те же поля, что форма
  на `/zapis/`, в том же порядке: согласие с политикой конфиденциальности → имя → телефон → услуга → день и час →
  марка → что случилось → проверка → «Отправить заявку».

Обе ветки проходят через общий узел «Проверка и очистка» (серверная валидация) и «Строка в таблицу».
Админский бот присылает уведомление: «Новая заявка с сайта» или «Новая заявка из Telegram-бота» с @username клиента.
Последний столбец «Источник»: `telegram` — заявка из бота; с сайта — `utm_source` из ссылки, по которой пришёл
посетитель (метка помнится до конца сессии браузера), без метки — `web`. n8n ищет столбцы по заголовкам:
в боевой таблице в первой строке должен быть заголовок «Источник» (столбец I).

## Боты и учётные данные

| Credentials в n8n       | Что это                                       | Узлы |
|-------------------------|-----------------------------------------------|------|
| `BOT_TOKEN_TG`          | админский бот: уведомления о заявках          | «Сообщение в Telegram», «Тревога в Telegram» |
| `BOT_CLIENT_TOKEN_TG`   | клиентский бот: диалог записи                 | «Сообщение клиентскому боту», «Бот: …», «Клиенту: …» |
| `GOOGLE_SHEETS_ACCOUNT` | доступ к таблице                              | «Строка в таблицу» |
| `TURNSTILE_SECRET`      | секретный ключ капчи (Custom Auth)            | «Проверка капчи» |

`CHAT_ID_TG` — id чата админа, в git остаётся заглушкой. Токены — только в n8n → Credentials, никогда в файлах.

## Капча на сайте (Cloudflare Turnstile)

Как выглядит — демо-страница `/captcha/` на тестовых ключах Cloudflare. В форме сейчас **выключена**: `TURNSTILE_SITE_KEY` в `js/config.js` пустой, `CAPTCHA_REQUIRED = false` в «Проверке и очистке».
Форма работает как без капчи, ветка «Нужна капча?» → «Строка в таблицу» идёт мимо проверки. Бот капчу не проходит никогда.

Включать строго в этом порядке, иначе заявки с сайта перестанут приниматься:

1. Cloudflare → Turnstile → Add widget: домен сайта (`quillonlending.vercel.app`, для проверки можно добавить `localhost`),
   режим Managed. Получите два ключа: Site Key (публичный) и Secret Key.
2. Сайт: Site Key → `TURNSTILE_SITE_KEY` в `js/config.js`. Домен `https://challenges.cloudflare.com` в CSP (`script-src`,
   `frame-src`) уже есть — его добавили для демо-страницы `/captcha/`; без него сборка упадёт.
   Политика конфиденциальности дополнится строкой про Cloudflare сама. Задеплоить и проверить, что виджет виден.
3. n8n → Credentials → New → **Custom Auth**, имя `TURNSTILE_SECRET`, JSON: `{"body": {"secret": "<Secret Key>"}}`.
   Выбрать его в узле «Проверка капчи».
4. В «Проверке и очистке» (в n8n и в этом файле) поставить `CAPTCHA_REQUIRED = true`, сохранить, переактивировать.
5. Отправить заявку с сайта: строка в таблице. Запрос в обход формы без токена получит 400, с неверным токеном — 403.

Сборка не даст поставить `CAPTCHA_REQUIRED = true` при пустом ключе на сайте. Выключать — в обратном порядке:
сначала `false` в n8n, потом ключ на сайте.

## Подключить клиентского бота

1. В @BotFather: `/newbot` → имя и username бота → токен. Там же `/setdescription` и `/setcommands`
   (`start — Записаться`).
2. n8n → Credentials → New → Telegram API: вставить токен, назвать `BOT_CLIENT_TOKEN_TG`.
3. Импортировать воркфлоу (локальная копия с id чата — `n8n/local/shesterenka-leads.ready.json`), в узлах клиентского
   бота выбрать `BOT_CLIENT_TOKEN_TG`, в узлах админского — `BOT_TOKEN_TG`.
4. **Активировать** воркфлоу. n8n сам зарегистрирует вебхук бота в Telegram.
5. Написать боту `/start` и пройти запись до конца — строка в таблице, уведомление админу, «Заявка принята» в боте.

## Что важно знать

- **Состояние диалога** хранится в static data воркфлоу и сохраняется только у **активного** воркфлоу:
  в ручном запуске (Test workflow) бот каждый раз начинает с начала. Кнопка Test workflow ещё и временно
  перехватывает вебхук бота — после теста воркфлоу нужно деактивировать и активировать заново.
  Незавершённые диалоги удаляются через сутки. При двух клиентах, пишущих боту одновременно, шаг одного
  может потеряться (static data пишется целиком) — если поток вырастет, перенести состояние в n8n Data Tables или Redis.
- **Лимит заявок с сайта** — 500 в час на всех (`LIMIT_PER_HOUR` в узле «Лимит заявок», скользящее окно в static data).
  Сверх лимита вебхук отвечает 429 с `Retry-After`, отклонённые запросы в счёт не идут. Бот идёт мимо лимита:
  у него своё ограничение — одна заявка в минуту с чата. Счётчик живёт только у активного воркфлоу; при
  одновременных запросах static data может недосчитать несколько штук — для защиты от спама это допустимо.
- **Те же правила, что на сайте:** день — из ближайших 14 (`booking.daysAhead`), кроме выходных; час — по режиму
  работы, сегодня — не раньше чем через час; одна заявка в минуту с одного чата; группы бот игнорирует.
- **Зашито в коде узлов** и сверяется сборкой с `content/`: `SCHEDULE` (оба Code-узла), `SERVICES`, `DAYS_AHEAD`,
  `SITE_URL` («Диалог бота»). Поменяли часы, услуги или домен — правьте узел в n8n и этот файл, иначе
  `node scripts/build.mjs` упадёт.
- В узле «Бот: семь кнопок» ровно 7 кнопок: 6 услуг + «Не знаю, нужна консультация» и 6 дней + «Любой день».
  Если число услуг изменится, добавьте или уберите кнопку в этом узле.
- Ссылка на политику — `SITE_URL/privacy.html`: тот же документ, что под формой на сайте; в нём описан и бот.
