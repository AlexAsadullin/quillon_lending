# Сайт автосервиса «Шестерёнка» (Москва)

## Главные правила (важнее всего остального в этом файле)

1. **Факты — только из `content/`.** Цены, гарантии, часы, адрес, телефон, оборудование, число постов —
   только то, что есть в `content/` с источником (пункт прайса, регламент, договор).
   `content/` наполняется только из документов клиента в `Архив/` (прайс, регламент, договор,
   «акции и скидки»; переписка — не источник). `Архив/` в git не попадает.
   Нет факта → пишем «[уточнить у владельца]» и добавляем строку в `content/probely.md`. Не придумываем.
2. **Нет отзывов, стоковых фото и сроков.** Ни выдуманных отзывов, ни «опыта N лет», ни сроков работ
   («за 2 часа», «за 15 минут»), ни «от» и «под ключ» в ценах. Сборка падает на таких словах в `content/`.
3. **Шапка, меню, подвал — в одном месте:** `templates/partials/header.html` и `footer.html`.
   В страницах их не копировать — только `{{> header}}` и `{{> footer}}`.
4. **Вид — по `design.md`.** Цвета, шрифт, размеры, отступы, кнопка, карточка. Расходится с этим файлом —
   прав `design.md`.
5. **Новая страница сразу в меню и в карте.** Страница добавляется одной записью в `PAGES`
   в `scripts/build.mjs` (с подписью `nav`) — из этого списка строятся меню шапки и подвала и `sitemap.xml`.
   Страницы услуг добавляются файлом в `content/services/` и попадают в каталог, подвал и карту сами.

Статичный сайт: HTML + CSS + ванильный JS. Тексты и цены лежат в `content/`, страницы
собираются из шаблонов `templates/` скриптом `scripts/build.mjs` — только встроенные модули Node,
без npm, фреймворков и зависимостей. Новых зависимостей не добавлять.

```bash
node scripts/build.mjs                    # сборка в dist/
python3 -m http.server 8080 -d dist       # просмотр на http://localhost:8080
```

Vercel при пуше в `main` сам запускает сборку и публикует **только `dist/`** (см. `vercel.json`).

## Акции и скидки

- Источник — только файл `Архив/акции и скидки` (и п. 14 прайса). Он меняется чаще остальных документов:
  при каждом изменении файла — привести `content/akcii_predlozheniya.json` к нему **полностью**:
  новая акция → добавить, исчезнувшая из файла → убрать с сайта, изменённые цифры → заменить.
- Переносить только то, что написано в файле. Сроки действия, «первое ТО», на что распространяется скидка,
  суммируется ли с другими условиями — если в файле этого нет, на сайт не дописывать, а занести в `probely.md`.
- У каждой акции — поле `source` (документ). Страница `/akcii-predlozheniya/`, при сборке проверяется на запрещённые слова.
«О нас» и «Отзывы» нет — для них нет фактов. `sitemap.xml` и `robots.txt` генерируются при сборке.

Новые файлы класть в эти папки. Не плодить отдельные CSS/JS-файлы под каждую секцию.

## 0. Контент и сборка

- Тексты, цены, контакты правятся **только в `content/`**, не в шаблонах и не в `dist/`.
  В шаблонах — только разметка и постоянные подписи интерфейса.
- Цена хранится один раз — в `content/prices.json`. В остальных текстах — подстановки
  `{price.7}`, `{cond.13}`, `{condText.14}`, `{terms.guarantee.works}`; цифры руками не переписывать.
- Цена = цена работы + «Запчасти отдельно (п. 12)». Рядом с цифрой — пункт прайса.
- Шаблонизатор: `{{path}}` — с экранированием (по умолчанию), `{{{path}}}` — готовый HTML,
  только для значений, которые формирует сам `build.mjs`. `{{> partial}}`, `{{#each}}`, `{{#if}}` — без вложенности.
- Сборка падает на неизвестном теге, пустом обязательном поле, повторе slug, ссылке услуги
  на несуществующий пункт прайса, работе прайса без услуги, запрещённых словах (правило 2),
  `title` длиннее 60 символов, «лучший» и «№1» в `title`/`description` и на домене формы, которого нет в CSP. Не обходить эти проверки — чинить причину.
- Пути в шаблонах — через `{{root}}` (относительный путь до корня), ссылка на главную — `{{homeUrl}}`.
- Всё, что есть в `content/` (кроме `docs/`), публикуется. Реквизиты, договоры, персональные данные —
  только в `content/docs/`.

## 1. Чистый код

### Общее
- Язык интерфейса — русский. Комментарии в коде — русские, короткие, объясняют «зачем», а не «что».
- Отступ 2 пробела, UTF-8, LF, в конце файла — перевод строки.
- Никакого мёртвого кода, закомментированных блоков, `console.log` в финальной версии
  (допустим `console.warn` для ошибок конфигурации).
- Одна ответственность у функции. Функция длиннее ~40 строк — повод разбить.

### HTML
- Семантика: `header`, `nav`, `main`, `section` с `aria-labelledby`, `footer`, `address`.
  Один `h1` на страницу, заголовки по порядку без пропусков уровней.
- Никаких inline-стилей (`style="..."`) и inline-обработчиков (`onclick="..."`) — это ломает CSP.
- У всех `<img>` — `alt`, `width`, `height`, `loading="lazy"` (кроме первого экрана).
  Декоративные SVG — `aria-hidden="true"`.
- Повторяющаяся графика (шестерёнка) — через `<symbol>` + `<use>`, а не копипастой.
- Телефоны — `<a href="tel:+7...">`, адрес — внутри `<address>`.

### CSS
- Все цвета, шрифты, отступы, радиусы, тени — только через custom properties из `:root`.
  Хардкод цвета в правиле = ошибка ревью.
- Именование классов — BEM: `.block`, `.block__element`, `.block--modifier`.
  Состояния — `.is-open`, `.is-sent`, `.is-invalid`.
- Mobile-first: базовые стили для телефона, `@media (min-width: ...)` — для больших экранов.
- Размеры шрифтов — `clamp()`, никаких `px` для типографики.
- Не использовать `!important` (исключение — правило `prefers-reduced-motion`).
- Вложенность селекторов — не глубже 3 уровней.

### JavaScript
- ES2020+, `'use strict'` внутри модуля, `const` по умолчанию, `let` при переприсваивании, без `var`.
- Без библиотек. Нужна библиотека — сначала обосновать, почему без неё нельзя.
- Каждая фича — отдельная функция `initXxx()`, вызывается из одного места в конце `main.js`.
  Функция обязана молча выходить, если нужного элемента нет на странице.
- Селекторы для JS — через `data-*` атрибуты (`data-js="..."`), а не через классы стилей.
- Работа с DOM — `textContent`, `classList`, `setAttribute`. **`innerHTML` с данными запрещён.**
- Ошибки сети и валидации всегда показываются пользователю понятным текстом, а не глотаются.

## 2. Безопасность

- **Токены Telegram-ботов** — только в n8n → Credentials. Ботов два: админский (уведомления о заявках) и клиентский
  (запись через Telegram). В `n8n/shesterenka-leads.json` остаются заглушки `BOT_TOKEN_TG` (админский бот),
  `BOT_CLIENT_TOKEN_TG` (клиентский бот) и `CHAT_ID_TG` (id чата админа). Сборка падает, если найдёт токен в `n8n/` или `js/`.
- **Никаких секретов в коде.** Токены ботов Telegram, ключи API, пароли — никогда не попадают
  в HTML/JS: всё, что лежит в статике, видно любому посетителю. Форма отправляется на внешний
  обработчик (n8n webhook, свой бэкенд, Formspree и т.п.), а уже он держит секреты.
  Адрес обработчика задаётся в `js/config.js` → `FORM_ENDPOINT`.
- **CSP** живёт в одном месте — `vercel.json` (HTTP-заголовок). Сборка копирует ту же политику
  в мета-тег каждой страницы (без `frame-ancestors`, который в мета-теге не работает).
  Домен обработчика формы **обязательно** в `connect-src` — иначе сборка упадёт.
  Не ослаблять политику до `*` или `'unsafe-inline'`.
- Там же заголовки `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`;
  HSTS на `*.vercel.app` Vercel ставит сам.
- **Публикуется только `dist/`.** В `scripts/build.mjs` → `STATIC_DIRS` перечислено всё,
  что копируется как есть. Не добавлять туда `content/`, `n8n/`, `.claude/` и корень проекта.
- **Форма:**
  - Валидация на клиенте — только для удобства. Обработчик на сервере обязан валидировать повторно
    (узел «Проверка и очистка» в `n8n/shesterenka-leads.json`). Новое поле формы = правка и там,
    и шаг в узле «Диалог бота» (клиентский бот спрашивает те же поля в том же порядке).
  - Запись на время — предварительная: занятость постов не проверяется, время подтверждаем по телефону.
    Слоты строятся из режима работы (`content/site.json` → `schedule`, по регламенту) по `Europe/Moscow`:
    выходные не предлагаются, последний слот — за час до закрытия. Тот же режим зашит в узел
    «Проверка и очистка» и «Диалог бота» в n8n (`SCHEDULE`), в боте ещё `SERVICES`, `DAYS_AHEAD`, `SITE_URL` —
    меняете часы, услуги или домен, меняйте и там. Сборка сверяет их с `content/` и падает при расхождении.
  - Honeypot-поле (`website`) против ботов: если заполнено — заявку не отправлять.
  - Ограничение частоты: не чаще одной отправки в 60 секунд с одной вкладки.
  - Ограничение длины полей (`maxlength`) и обрезка пробелов.
  - Обязательный чекбокс согласия на обработку ПДн со ссылкой на `privacy.html` (152-ФЗ).
  - Отправка — `fetch` с `POST`, `Content-Type: application/json`, таймаут через `AbortController`.
- Внешние ссылки с `target="_blank"` — всегда `rel="noopener noreferrer"`.
- Внешние ресурсы — только Google Fonts. Новые CDN не подключать без правки CSP и причины.
- Не использовать `eval`, `new Function`, `document.write`, строковый `setTimeout`.

## 3. Дизайн и интерфейс

Всё о виде — в **`design.md`**: графит, оранжевый и бумага; один шрифт Manrope; размеры заголовков;
шкала отступов 4 · 8 · 16 · 24 · 40 · 64; кнопка «Записаться»; карточка услуги; мобильный вид первым; без фото.
Фирменные элементы: миллиметровка, размерные линии, шестерёнка от прокрутки, заказ-наряд со штампом «Принято».

### Интерфейс и доступность
- Всё работает с клавиатуры. Видимый `:focus-visible` у всех интерактивных элементов.
- Есть ссылка «Перейти к содержимому» для скринридеров.
- Кликабельные зоны — не меньше 44×44px.
- Ошибки формы — текстом под полем + `aria-invalid` + `aria-describedby`; статус отправки — в `aria-live`.
- Анимации — только `transform` и `opacity`. Уважать `prefers-reduced-motion`: всё вращение
  и появление отключается.
- Проверять вёрстку на ширинах 360, 768, 1280, 1920.

## 4. Самопроверка перед сдачей

Перед тем как сказать «готово», пройти по списку:

0. Сборка проходит: `node scripts/build.mjs`.
1. HTML валиден: `npx html-validate $(find dist -name '*.html')`.
2. JS без синтаксических ошибок: `node --check js/main.js js/config.js scripts/build.mjs`.
3. `grep -rn "innerHTML\|eval(\|style=\"\|onclick=" templates js` — пусто.
4. `grep -rn "token\|apikey\|api_key\|secret" js/` — пусто (секретов нет).
5. Все `id`, на которые ссылаются `href="#..."`, `aria-*`, `<use href>`, существуют — на каждой
   странице `dist/`. Относительные ссылки между страницами ведут на существующие файлы.
6. Все цвета в `style.css` берутся из токенов (хардкод — только внутри `:root`).
7. Форма: пустая отправка → ошибки у полей; неверный телефон → ошибка; без согласия → ошибка;
   повторная отправка раньше 60 с → предупреждение. Время записи недоступно, пока не выбран день;
   сегодня предлагаются только часы не раньше чем через час. Кнопка «Записаться» на услуге →
   `/zapis/?usluga=<slug>` → услуга выбрана в форме.
   Тестовые заявки не отправлять в боевой вебхук — подменять `FORM_ENDPOINT` при проверке.
8. Страница открывается без консольных ошибок, в том числе ошибок CSP.
9. `prefers-reduced-motion: reduce` — анимации остановлены.
10. Правило 5: каждая страница без noindex есть в `dist/sitemap.xml` и в меню/подвале каждой страницы.
11. Правило 1: все суммы «N ₽» в `dist/` есть в `content/prices.json` (и 25 000 из п. 14).
12. Правило 2: `grep -rniE "отзыв|опыт|лет на рынке|под ключ|[^а-я]от [0-9]" content/` — пусто
    (кроме `probely.md`, где эти слова — в списке того, чего нет).
13. На всех страницах один шрифт — Manrope (`getComputedStyle` у всех элементов).
14. Перед публикацией — скилл `/proverka-faktury`: сайт против фактуры, находки разобрать вручную.
15. Приёмка — проектный скилл `.claude/skills/priemka/SKILL.md` (13 пунктов, включая акции и скидки).

## Пробелы в фактуре

Всё, чего нет в документах `Архив/`, — в `content/probely.md`. Телефон, адрес и реквизиты оператора ПДн
сейчас ТЕСТОВЫЕ (флаг `"test": true` в `content/site.json`, подпись в подвале): выбраны так, чтобы не совпасть
с реальными, и не отдаются в микроразметку. Новые тестовые данные — только такие же заведомо несуществующие.
`url` в `content/site.json` — заменить на боевой домен, когда он появится.
