# Шестерёнка — сайт автосервиса в Москве

Статичный сайт автосервиса «Шестерёнка» из фактуры: 12 страниц, каждая цифра — из прайса
с номером пункта, чего нет в документах — «[уточнить у владельца]». Тексты и цены лежат в `content/`,
страницы собираются из шаблонов скриптом на Node без зависимостей. Вид — по [design.md](design.md).

Дизайн-концепция — «технический чертёж»: миллиметровка, размерные линии, шестерёнка,
которая вращается при прокрутке, и форма записи в виде отрывного заказ-наряда
со штампом «Принято».

## Запуск

```bash
git clone https://github.com/AlexAsadullin/quillon_lending.git
cd quillon_lending
node scripts/build.mjs                  # сборка в dist/
python3 -m http.server 8080 -d dist     # http://localhost:8080
```

Нужен только Node.js 18+, `npm install` не требуется.

## Карта сайта

| Адрес                    | Страница                                         |
|--------------------------|--------------------------------------------------|
| `/`                      | главная: что делаем, гарантия и условия, часы и запись |
| `/uslugi/`               | каталог услуг                                    |

| `/garantiya-i-oplata/`   | гарантия, оплата, выдача, отказ и возврат        |
| `/voprosy/`              | вопросы и ответы со ссылками на пункты           |
| `/akcii-predlozheniya/`  | акции и предложения: только из прайса (п. 14)    |
| `/privacy.html`, `/404.html` | вне меню и карты, noindex                    |
| `/captcha/`              | демо капчи Cloudflare Turnstile на тестовых ключах; вне меню и карты, noindex |

Меню шапки и подвала и `sitemap.xml` строятся из одного списка `PAGES` в `scripts/build.mjs`.
«О нас» и «Отзывы» нет — для них нет фактов (см. `content/probely.md`).

## Структура

```
content/            — факты сайта: прайс, услуги, условия, FAQ (как править — content/README.md)
design.md           — правила вида: цвета, шрифт, размеры, кнопка, карточка
content/docs/       — документы автосервиса: не публикуются и не попадают в git
templates/          — шаблоны страниц и общие части
scripts/build.mjs   — сборка: content + templates → dist/
css/, js/, assets/  — стили, скрипты, картинки (копируются в dist/ как есть)
n8n/                — воркфлоу приёма заявок и шаблон Google Таблицы
vercel.json         — сборка на Vercel и заголовки безопасности (CSP)
.claude/CLAUDE.md   — правила кода, безопасности и дизайна
```

## Деплой

Vercel при каждом пуше в `main` запускает `node scripts/build.mjs` и публикует только `dist/`.
Исходники, `content/docs/`, `n8n/` и служебные файлы на сайт не попадают.

## Форма записи

Заявка уходит `POST`-запросом с JSON на вебхук n8n (`js/config.js` → `FORM_ENDPOINT`):

```json
{
  "name": "Иван",
  "phone": "+79161234567",
  "car": "Kia Rio 2018",
  "service": "Ремень ГРМ",
  "problem": "Стучит спереди справа на кочках",
  "visitDate": "2026-10-21",
  "visitTime": "10:00",
  "consent": true,
  "page": "https://quillonlending.vercel.app/zapis/?usluga=grm",
  "sentAt": "2026-10-19T10:00:00.000Z"
}
```

Запись предварительная: сайт предлагает дни на `booking.daysAhead` вперёд и часы с `firstSlot`
до `lastSlot` по Москве (`content/site.json`). Сегодня — только часы не раньше чем через час.
Занятость постов не проверяется, время подтверждает мастер по телефону.
Форма — на `/zapis/`. Кнопка «Записаться» на услуге ведёт на `/zapis/?usluga=<slug>`, услуга выбирается сама.

### Заявки → n8n → Google Таблица + Telegram

Воркфлоу: [n8n/shesterenka-leads.json](n8n/shesterenka-leads.json).

```
Webhook (POST) → проверка и очистка → данные корректны?
  ├─ да  → строка в Google Таблицу ─┬─ ответ 200 { ok: true }          → «Новая заявка» в Telegram
  │                                 └─ сбой → ответ 502 { ok: false } → «ЗАЯВКА НЕ ЗАПИСАНА» в Telegram
  └─ нет → ответ 400 { ok: false, error }
```

1. **Таблица** — настоящая Google Таблица (не загруженный `.xlsx`: ссылка без `rtpof=true`).
   Лист `Заявки`, строка заголовков ровно такая:

   | Имя | Телефон | Марка | Услуга | Что случилось | Запись | Время | Статус |
   |-----|---------|-------|--------|---------------|--------|-------|--------|

   Шаблон с выпадающим списком статусов: [n8n/shesterenka-leads-template.xlsx](n8n/shesterenka-leads-template.xlsx) —
   загрузите в Google Диск и выберите *Файл → Сохранить как Google Таблицу*.
2. **Импорт** в n8n: удалите старую версию воркфлоу, затем *Workflows → Import from File*.
3. **Узел «Строка в таблицу»:** проверьте учётные данные Google и таблицу.
4. **Active** — включить. Production URL (`/webhook/…`, не `/webhook-test/`) — в `FORM_ENDPOINT`,
   домен n8n — в `connect-src` в `vercel.json`. Сборка проверит, что домен там есть.

Воркфлоу повторно проверяет все поля (имя, телефон, согласие, услуга, дата и время визита),
ставит время приёма по Москве, пишет значения в режиме RAW (формула из формы не выполнится)
и принимает запросы только с `https://quillonlending.vercel.app`.

> Секреты в `js/config.js` класть нельзя: файл скачивает каждый посетитель.

### Telegram: куда вписать токен и чат

В воркфлоу два узла Telegram — **«Сообщение в Telegram»** и **«Тревога в Telegram»**. В обоих две заглушки:

| Заглушка      | Где в узле              | Что вписать                         | Где хранится                         |
|---------------|-------------------------|-------------------------------------|--------------------------------------|
| `BOT_TOKEN_TG`| поле **Credential**     | токен бота от @BotFather            | n8n → Credentials (зашифрован)       |
| `CHAT_ID_TG`  | поле **Chat ID**        | id чата, куда слать заявки          | в узле                               |

1. **Бот.** В Telegram откройте @BotFather → `/newbot` → получите токен вида `1234567890:AA…`.
2. **Токен — в n8n, не в репозиторий.** n8n → *Credentials* → *Add credential* → **Telegram API** →
   поле **Access Token** = токен → сохраните (например, как «Telegram — Шестерёнка»).
   Затем в узлах «Сообщение в Telegram» и «Тревога в Telegram» в поле **Credential** выберите его
   вместо `BOT_TOKEN_TG`.
3. **Чат.** Напишите боту любое сообщение (или добавьте бота в рабочую группу и напишите там).
   Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе найдите
   `"chat":{"id": …}`. У групп id отрицательный, например `-1001234567890`. Ссылку с токеном никому не пересылайте.
4. В обоих узлах в поле **Chat ID** замените `CHAT_ID_TG` на этот id. Сохраните воркфлоу.
5. **Проверка.** *Execute workflow* → тестовая заявка на `/webhook-test/…` → сообщение в Telegram.

> Токен **никогда** не вписывайте в `n8n/shesterenka-leads.json` в проекте — репозиторий публичный.
> Сборка сайта упадёт, если найдёт в `n8n/` или `js/` что-то похожее на токен. При экспорте из n8n токен
> в файл не попадает: в JSON остаётся только имя учётных данных. Если токен всё же оказался в git —
> перевыпустите его у @BotFather (`/revoke`).
